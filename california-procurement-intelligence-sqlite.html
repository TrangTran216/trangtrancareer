Objective

Turn a large public CSV into an auditable reporting workflow.

I built a reproducible SQLite process that keeps the raw source intact, standardizes text and currency fields through a reusable view, audits data quality, analyzes procurement records across several dimensions, normalizes departments through a lookup-table join, and creates a reusable reporting summary.

The project is designed to demonstrate practical SQL, careful handling of public records, and validation discipline—not merely produce ranked totals.

Database architecture

Raw source preserved; analysis built in reusable layers.

The raw table remains unchanged. A clean view supplies standardized fields, and relational objects support validated reporting.

Workflow

How the project was built

  1. 01Verify the raw import.Confirmed 344,504 records and preserved the original 32-column source table without destructive edits.
  2. 02Create a cleaned view.Standardized headings, trimmed text, converted blanks to NULL, parsed formatted currency, retained traceable source row IDs, and created quality flags.
  3. 03Audit data quality.Measured missing departments, suppliers, and amounts; reviewed repeated purchase-order identifiers; and performed a stricter exact-duplicate audit.
  4. 04Analyze procurement records.Used aggregate queries for departments, suppliers, UNSPSC commodities, fiscal years, overall statistics, and amount buckets.
  5. 05Normalize and join.Created a department lookup with a primary key and unique constraint, then validated a LEFT JOIN with zero unmatched nonmissing departments.
  6. 06Summarize and reconcile.Built an indexed 150,297-row reporting table and verified that both line counts and total reported value matched the clean source.

Data-quality audit

Missing values and repeated identifiers were measured, not guessed away.

0missing department records
36records missing both supplier code and name
30records with no purchase amount
33,956PO identifiers appearing on multiple lines
1,305exact duplicate value groups
2,087extra exact duplicate rows beyond the first copies

Repeated purchase-order numbers were treated as review candidates because multi-item orders can legitimately occupy multiple source lines. Exact duplicates were documented rather than deleted without a business rule.

Scope and interpretation

Historical public procurement records—not audited payment conclusions.

The source is the California Department of General Services “Purchase Order Data 2012–2015” dataset. Reported amounts in this project are source-line values from that file. Findings are limited to the available historical records and should not be generalized beyond the dataset.
